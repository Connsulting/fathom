Fathom
Architectureone container, one store

How Fathom fits together

One Node process serves the Horizon app, the JSON API and MCP, runs its own jobs, and keeps all state on the /data volume.

HTTP server and router
src/server.mjs · src/api/router.mjs
Opens the store by mode, then builds the engine, packs, mail transport and scheduler. One route table, one Host allowlist for /api and /mcp, security headers on every response.
MCP endpoint
POST /mcp · src/mcp/
Stateless Streamable HTTP. Keys are kept as HMACs; scopes are read and write:recs.
Session gate and accounts
src/auth/
Passkeys over WebAuthn, the __Host-fathom-session cookie, exact Origin on every mutation.
Horizon web app
web/horizon/ · static
No build step: design.js and design.css, plus the account pages in web/auth/.
Tool registry
src/tools/
19 tools over stored data, shared by the engine and MCP: 17 read, 2 write:recs.
JSON API
/api · src/api/
Plan, confirm, goals, Ask threads, keys, email and jobs. Ask answers stream as Server-Sent Events.
Ingest
src/ingest/ · parsers/ · simplefin.mjs
Uploads run through one parser per source format into ledger rows. SimpleFIN sync lands here too.
Knowledge packs
packs/<id>/ · src/packs/
Seven curated packs, plus Your plans, built on the volume from the household's own plan documents.
Runtime engine
src/engine/
Modes live, fake, off. Purposes chat, job, extract, confirm and title, under a monthly spend cap.
Calculators
src/calc/
Deterministic tax, payroll, retirement room and pace. The planner and pace call them, and every figure they produce carries its provenance.
